# 사내 규정 RAG — 조항 단위 검색 + 출처 인용 답변

[![test](https://github.com/yochanpark/policy-rag/actions/workflows/test.yml/badge.svg)](https://github.com/yochanpark/policy-rag/actions/workflows/test.yml)

"서울 출장 숙박비 한도가 얼마야?"라고 물으면 **사내 규정에서 근거 조항을 찾아, 그 조항만 근거로 답하고 출처를 붙이는** 질의응답 예제다.
규정에 없는 질문에는 지어내지 않고 "규정에서 찾을 수 없습니다"로 답한다.

```
$ python -m rag ask "재택근무 중에 회사 노트북을 잃어버리면 어떻게 해야 해?"
자산을 분실하거나 파손하면 즉시 자산관리 담당자에게 알리고, 노트북·휴대전화는 정보보안 규정에 따라
정보보안팀에도 신고해야 합니다. 노트북 분실 등이 의심되면 즉시, 늦어도 1시간 안에 정보보안팀(내선 1119,
업무 시간 외에는 보안 당직 휴대전화)에 신고합니다.

출처: 자산관리규정 제5조, 정보보안규정 제7조
```

| 한눈에 | |
|---|---|
| 흐름 | 규정 문서 → **조항(제N조) 단위 분할** → 임베딩 → Chroma 저장 / 질문 → 검색(상위 4개) → **참조된 규정 따라가기** → 근거 조항만으로 답변 + 인용 |
| 출처 신뢰성 | 인용할 수 있는 조항 id를 응답 스키마의 `enum`으로 묶어, 검색되지 않은 조항이나 없는 조항을 인용할 수 없게 했다. 코드에서 한 번 더 거른다 |
| 모르면 거절 | 근거가 없으면 `answerable=false`. 평가 세트에 규정에 없는 질문 5개를 넣어 따로 잰다 |
| 검증 | 단위 테스트 12개(가짜 임베딩 + 실제 Chroma) + 실제 모델 평가 37문항 — [결과](#실제-모델-평가) |
| 비용 | 0원. Gemini API 무료 등급(임베딩·답변), 로컬 Chroma |
| 기술 | Python 3.12 · Chroma · Gemini API(OpenAI 호환 주소, `openai` SDK) · Structured Outputs · pytest · GitHub Actions |

문서는 이 예제를 위해 직접 쓴 **가상의 사내 규정 6개(조항 47개)** 다. 실제 회사와 관계없다.

## 구조

```
data/policies/*.md ──▶ chunk.py ──▶ llm.embed ──▶ store.add (Chroma, 파일 저장)
   근태·출장·보안·         조항 단위         gemini-embedding-001
   재택·자산·복리후생

질문 ──▶ llm.embed ──▶ store.search(k=4) ──▶ follow_references ──▶ llm.complete_json ──▶ 답 + 출처
                                             "○○ 규정에 따라"         인용 가능 id = 검색된 조항(enum)
                                             → 그 규정에서 1개 더
```

| 경로 | 역할 |
|---|---|
| [`rag/chunk.py`](rag/chunk.py) | `## 제N조 (제목)` 기준 분할. id는 `"근태휴가규정 제5조"`, 본문 앞에 문서·조항 제목을 붙인다 |
| [`rag/store.py`](rag/store.py) | Chroma(코사인). 파이프라인은 `add`·`search`만 쓴다 — 운영에선 이 두 메서드를 Azure AI Search로 바꿔 끼운다 |
| [`rag/pipeline.py`](rag/pipeline.py) | 적재, 검색, 참조 따라가기, 근거 답변과 인용 거르기 |
| [`rag/llm.py`](rag/llm.py) | `openai` SDK로 Gemini OpenAI 호환 주소 호출. 주소·모델만 바꾸면 OpenAI·Azure OpenAI |
| [`eval/`](eval) | 평가 문항 37개와 실행기 |
| [`tests/`](tests) | 모델 없이 도는 테스트 |

## 설계에서 고른 것

**조항 단위로 자른다.** 규정은 조항 하나가 규칙 하나다. 글자 수로 자르면 "① 5일 이상 연속 사용할 때는 14일 전까지"가
앞뒤 조항과 섞이거나 중간에서 끊긴다. 조항으로 자르면 출처가 곧 사람이 찾아볼 수 있는 위치(`근태휴가규정 제5조`)가 된다.
조항 본문만으로는 어느 규정인지 모르므로 임베딩할 때 `[근태 및 휴가 규정 제5조 (연차 휴가 사용)]`를 앞에 붙인다.

**인용은 스키마로 묶는다.** 프롬프트로 "검색된 조항만 인용하라"고 부탁하는 대신, 응답 스키마의 `citations` 항목을
검색된 id의 `enum`으로 만든다. 모델이 다른 id를 낼 수 없고, 그래도 혹시 모를 출력은 코드에서 걸러 낸다.

**참조된 규정을 따라간다.** 아래 [평가](#실제-모델-평가)에서 찾은 문제를 고친 것이다.

## 실제 모델 평가

[`eval/questions.json`](eval/questions.json)의 37문항을 실제 모델로 돌려 세 가지를 따로 잰다.
문항마다 **반드시 인용해야 할 조항**과 **답에 들어 있어야 할 사실**(숫자 등)을 정답으로 미리 적어 두었다.

| 묶음 | 문항 | 예 |
|---|---|---|
| 한 조항으로 답하는 질문 | 30 | "연차를 5일 연속으로 쓰려면 언제까지 신청해야 해?" → 근태휴가규정 제5조, "14일" |
| 헷갈리게 만든 질문 | (위에 포함) | "휴양소 숙박비는 회사가 얼마나 내줘?" — 출장 숙박비 조항과 겹치는 표현 |
| 두 규정에 걸친 질문 | 2 | "결혼하면 휴가랑 경조금은?" → 근태 제8조 + 복리후생 제4조 |
| 규정에 없는 질문 | 5 | "주차 지원금은?", "야근하면 저녁 식대가 나와?"(출장 식비 조항이 유혹) |

| 지표 | 결과 |
|---|---|
| 검색 — 인용해야 할 조항이 검색 결과에 들어왔나 (상위 4개 + 참조로 덧붙인 조항) | **34/34** |
| 답변 — 필요한 조항을 모두 인용하고 사실을 담았나 | **32/32** |
| 판단 — 없는 건 거절, 있는 건 답했나 | **37/37** |
| 전체 | **37/37** |

모델은 `gemini-embedding-001` + `gemini-3.5-flash-lite`(무료 등급), 2026-10-14 기준이다.

**처음에는 36/37이었다.** 틀린 한 문항은 "재택근무 중에 회사 노트북을 잃어버리면 어떻게 해야 해?"였고, 원인이 두 단계에 있었다.

1. **검색** — 정답 조항인 `정보보안규정 제7조`(1시간 안에 신고, 내선 1119)가 6위로 밀려 상위 4개에 들지 못했다.
   질문의 "재택근무"가 재택근무 규정 조항들을 끌어올렸다. 그런데 2위로 잡힌 `자산관리규정 제5조` 본문에 "**정보보안 규정에 따라** 신고한다"는 참조가 있었다.
   k를 늘려 이 문항만 맞추는 대신, 검색된 조항이 다른 규정을 가리키면 **그 규정 안에서 질문과 가장 가까운 조항 하나를 덧붙이도록** 했다(`follow_references`, [테스트](tests/test_pipeline.py)).
2. **답변** — 검색에 들어온 뒤에도 모델은 자산관리 조항 문장만 옮겨 적었다. 답변 지시문에 "다른 규정을 따르라고 하면 그 규정의 기한·연락처·절차도 함께 적고 인용한다"를 넣었다.

지시문을 바꾼 뒤에는 다른 문항이 나빠지지 않았는지 보려고 37문항 전체를 다시 돌렸다.

## 실행

```bash
python -m venv .venv && .venv/Scripts/activate      # macOS·Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # GEMINI_API_KEY 입력 (https://aistudio.google.com/apikey, 무료)
python -m pytest -q               # 모델·네트워크 없이 도는 테스트
python -m rag ingest              # 조항 47개 임베딩 → .chroma/
python -m rag ask "해외 출장 일비는 얼마야?"
EVAL_DELAY=4 python -m eval.run   # 실제 모델 평가 (무료 등급 분당 한도 때문에 4초 간격)
```

Windows 터미널에서 한글이 깨지면 `PYTHONUTF8=1`을 켠다.

## 운영으로 옮긴다면

| 이 예제 | 운영 |
|---|---|
| 로컬 Chroma | Azure AI Search — 벡터 + 키워드 하이브리드 검색, 문서 필터(`doc`)는 필터 쿼리로 |
| Gemini 무료 등급 | Azure OpenAI(임베딩·답변). `llm.py`의 주소·모델 이름만 바꾼다 |
| 마크다운 파일 | SharePoint 규정 라이브러리 → 변경 시 다시 적재(인덱서) |
| 명령줄 | Teams 봇이나 Copilot Studio에서 호출, 답변에 원문 링크 |
| 누구나 같은 답 | 문서 권한(보안 트리밍) — 사용자가 볼 수 있는 규정만 검색 |

## 범위와 한계

- 참조 따라가기는 `"○○ 규정에 따라"` 표현만 잡는다. "별표 2 참조", "제5조에 따른" 같은 조항 번호 참조는 아직 따라가지 않는다.
- 평가 세트는 직접 쓴 37문항이고 모델 한 조합으로만 돌렸다. 실제 직원 질문 분포를 대표하지는 않는다.
- 사실 확인은 문자열 포함 여부로 한다("12만 원" ↔ "12만원"처럼 공백만 무시). 같은 뜻을 다른 말로 쓰면 틀린 것으로 나올 수 있다.
- 규정 개정 이력(시행일)은 다루지 않는다. 운영에선 시행일 메타데이터로 현재 유효한 조항만 검색해야 한다.
